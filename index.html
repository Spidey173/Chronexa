📊 Engineering Decisions & Benchmark Telemetry

Comprehensive analysis of why Structured Lexical & Hybrid RRF beats generic dense vector search on enterprise work data.

🚨 The "Vector Search Trap" in Corporate RAG

  • Version & Date Blindness: Dense vector models give a cosine similarity of > 0.97 between "Route Planner v1" and "Route Planner v2". Vector search cannot distinguish historical version numbers or dates.
  • CPU Latency Bottleneck: Computing dense FastEmbed vectors across 1,316 units on CPU took 20–30s per request. Chronexa's BM25 index runs in < 1.7s.
  • Out-of-Vocabulary (OOV) Confusion: Corporate IDs (e.g. MTG-0916-GONOGO, U03SARAHK) get fragmented into meaningless subwords by standard vector tokenizers.

🛡️ Chronexa's 5 Core Pillars

  • 1. Pre-Retrieval Physical Boundary: Records where timestamp > as_of are completely excluded before indexing. 0% leakage mathematically guaranteed.
  • 2. ISO Timestamp Normalization: Dates like 2026-09-10 are indexed as individual temporal tokens (2026, sep, 10).
  • 3. Header Down-Weighting (0.35x): Message metadata like [Slack #route-planner] is down-weighted so bodies drive relevance.
  • 4. 1.8x Named Entity Boosting: Client codenames ("Acme Freight", "Sarah Patel") are boosted to avoid ambiguous matches.
  • 5. Reciprocal Rank Fusion (RRF): Sub-queries are fused to balance exact terms and semantic synonyms.
